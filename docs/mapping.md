# Codex to DSH event mapping

This document is the contract between a Codex rollout and a DSH session
artifact. It records what is translated, what is preserved, what is dropped,
and — most importantly — the structural invariants a synthesized artifact must
satisfy before the harness will load it.

Everything here was established by running DSH's own validators against
synthesized artifacts, not by reading type definitions. The rejection messages
quoted below are the real ones.

## 1. Why import is synthesis rather than migration

DSH versions its session format and ships an adjacent migration chain:
`v0→v1`, `v1→v2`, `v2→v3`. It is tempting to register "Codex rollout" as a
predecessor generation. That does not work, for two independent reasons.

**The catalog is build-static and first-party.** Its generated source says so
directly:

> `GENERATED by scripts/gen-session-format-catalog.ts — do not edit by hand.`
> `The direct imports make historical readability independent of mounted plugins.`

The catalog imports the three migration packages directly. Nothing a plugin
mounts can extend the chain.

**Adjacency is enforced.** `dsh-session-format` rejects any edge that is not
adjacent:

```js
if (sessionFormatVersion(migration.toVersion, ...) !== from + 1)
  throw new SessionFormatError(`${migration.name} must declare adjacent v${from}->v${from+1}`);
```

A foreign format has no integer predecessor in that lineage, so it cannot be an
edge at all.

**Consequence.** An importer must *synthesize* a current-generation artifact
directly. The public API for that is MIT-licensed and exported:

```js
import {
  releasedV3SessionFormatCodec,   // physical encoder
  assertReleasedV3Header,          // header validation
  restoreReleasedV3Artifact,       // whole-artifact validation
} from '@deepseek-ai/dsh-session-format-v2-to-v3';
```

`packages/dsh-session-artifact` uses exactly these, and
`_recon/spike/synthesize-v3-artifact.mjs` is the minimal executable proof that
a synthesized Codex-shaped session passes both validation layers.

## 2. Storage identity is a correctness constraint

DSH keeps no session registry. It discovers sessions by scanning
`<root>/<projectKey>/<sessionId>/`, and on load it recomputes the expected path
from the artifact's own header:

```js
const expectedPath = generationLogPath(this.root, meta.cwd, meta.id, storedVersion, this.compression);
if (path !== expectedPath && !await this.sameFile(path, expectedPath, signal))
  throw new Error(`corrupt session log "${path}": header id "${meta.id}" and cwd identify "${expectedPath}"`);
```

Two consequences shape every write:

- **`cwd` is part of the address.** Rewriting a working directory moves the
  session. `cwdRewrite` in `synthesizeSession` is therefore not cosmetic.
- **Duplicate ids across projects are fatal.** `findLog` searches every project
  directory and throws on a second match.

### 2.1 Path derivation

`projectKey` reproduces DSH's own function. Reproduced verbatim and verified
against every real session directory on the author's machine (43 at the time
of writing):

| Input | Output | Rule |
|---|---|---|
| `/a/b/c` | `--a-b-c--` | separators become `-` |
| `/a//b` | `--a-b--` | a separator run collapses |
| `/a/b/` | `--a-b---` | only *leading* dashes are stripped |
| `/a b` | `--a~0020b--` | unsafe code units escape as `~XXXX` |
| `/a~b` | `--a~007Eb--` | a literal tilde escapes too |
| `/` | `--root--` | an all-separator path falls back |

The transform is lossy by design: separators are not recoverable and the key is
truncated to 251 characters. Deriving a path anywhere other than
`sessionArtifactPath()` is how a writer ends up producing files the reader
rejects.

### 2.2 Compression is not generation

Compression and format generation are independent axes, and the filename
encodes both: `session.jsonl.zstd` is generation 0, compressed.
`session.v3.jsonl.zstd` is generation 3, compressed.

Measured on the author's machine: **4 sessions at generation 0, 39 at
generation 3.** An early version of `discoverArtifacts` inferred "plaintext"
from `version === 0` and silently dropped all four. The reader now takes
compression from the filename suffix and the generation from the numeric
component, never one from the other.

Two further details follow:

- A header must declare the generation its filename claims. Verified against
  every session on this machine.
- Generation 0 headers carry **no `isSeeded` field**. Requiredness begins at
  generation 1, which is why `SessionHeader.isSeeded` is optional.

## 3. Structural invariants

TypeScript's types do not express these. Each was found by running the
installed `Session` validator and reading the rejection.

| # | Invariant | Rejection |
|---|---|---|
| **C1** | Message-bearing events carry `surfaceOp` | `format v3 assistant/message at seq 3 requires a surfaceOp marker` |
| **C2** | Message envelopes carry a non-empty string `id` | `seed assistant/message at index 3 lacks an identified message` |
| **C3** | `assistant/message` carries `turn`, `step`, and a `stream` array | `seed assistant/message at index 3 has invalid settlement fields` |
| **C4** | `seq` is contiguous from 0 | `released v2 row 8 has seq gap (expected 8, got 900)` |
| **C5** | Unknown event types carry `ignorable: true` | surfaced through the surface fold |

### C1 — the surface-eligible set

Only four types require a marker. Measured directly:

```
SURFACE  user/message      SURFACE  assistant/message
SURFACE  tool/result       SURFACE  system/message
```

`turn/start`, `turn/end`, `step/start`, `step/end`, `tool/call`, and
`request/context` are not surface-eligible and must **not** carry one.

### C3 — `stream` may be empty

`assistant/message` embeds an incremental stream: `{type: 'chunk', time,
chunk: {type: 'block-start', index, blockType}}` and friends. A real session on
this machine carries eleven such records.

An importer has no stream data, because a rollout records settled content.
Measured: `stream: []` passes every validator, and the content is carried by
`message.content` regardless. This removes the single largest implementation
cost that a naive reading of the format would imply.

### C4 — contiguity is a gift

`seq` must be exactly `0, 1, 2, …`. The builder owns the counter, so no caller
can violate it. Contiguity also means the importer's sequence numbers are
independent of Codex's, which is what makes the mapping order-driven rather
than identity-driven.

### C5 — a capability difference between the two write paths

`dsh-session/types/surface.js` reads:

```js
if (!KNOWN_SESSION_EVENT_TYPES.has(event.type) && event.ignorable === true) ...
```

An unrecognized type without the flag is a fold error, so a naive
"preserve everything" importer fails on exactly the data it was trying hardest
to keep.

**What matters is that the flag is not reachable from every write path.** The
read side refuses unknown types unless `event.ignorable === true`
(`dsh-session-persistence/lib/index.js:1117-1121`). The public write side cannot
supply it: `Session.append` threads only `sourceEventSeqs` and `surfaceOp`
(`dsh-session/lib/index.js:1437-1447`), and the generated vocabulary file states
that out-of-repo plugin events "are outside this list by construction; a
registration surface for them is deferred until such a consumer exists".

So the two write paths differ in what they can express:

| Write path | Can set `ignorable` | Must derive the storage path |
|---|---|---|
| `SessionPersistence.create` + `append`, or `agents.create` | **No** | No — the host does |
| Hand-encoded artifact | **Yes** | Yes |

Two plugin authors met this wall from opposite sides, which is the evidence that
it is structural rather than a local mistake. `@morlay/ui-conversation-message-actions`
names it in a source comment and bypasses `append` to write the envelope itself.
`dsh-omni-router` 2.4.0 calls `session.append('omni/router', …)` normally and
therefore emits an unknown type with no marker; those sessions are refused at
load by this build.

**Correction.** An earlier revision of this document described the flag as a
deliberate choice, and described `dsh-chat-import` as deliberately declining to
use it. That was wrong: it writes through the host API, where the flag is not
available. Its behaviour is constrained by its architecture, not chosen.

This repository hand-encodes, so its preserved events do carry the flag —
verified in `packages/dsh-session-artifact/test/artifact.test.mjs`.

## 4. The mapping table

The table below is a specification, not a code symbol. There is no
`DEFAULT_MAPPING` object in this repository and no `codex-to-dsh mapping` command
to print it; both stood here before and neither was ever written. The mapping is
carried by `lib/convert/codex.mjs` (vendored upstream, unmodified) and, for the
artifact side, by `packages/dsh-session-artifact`. Treating a change here as a
fidelity change is correct, because a session imported under an older table is
not identical to one imported under a newer one.

### Translated

| Codex | DSH | Note |
|---|---|---|
| `session_meta` | session header | `base_instructions` is not carried |
| `turn_context` | `request/context` | model and provider only |
| `response_item/message` (user) | `user/message` | |
| `response_item/message` (assistant) | `assistant/message` | `stream: []` |
| `response_item/message` (developer, system) | `system/message` | |
| `function_call`, `custom_tool_call` | `tool/call` | |
| `function_call_output`, `custom_tool_call_output` | `tool/result` | |
| `tool_search_call` / `_output` | `tool/call` / `tool/result` | |
| `patch_apply_end` | `tool/result` | stdout and stderr joined |
| `web_search_call` | `tool/call` | identified by `id`, not `call_id` |
| `web_search_end` | `tool/result` | identified by `call_id` |
| `event_msg/task_started` | `turn/start` | |
| `event_msg/task_complete` | `turn/end` | |
| `event_msg/turn_aborted` | `turn/end` (aborted) | |
| `event_msg/item_completed` | `step/end` | |

### Preserved as `ignorable`

| Codex | Emitted as | Why preserved |
|---|---|---|
| `response_item/reasoning`, `event_msg/agent_reasoning` | `codex/reasoning` | readable summary text; ciphertext excluded |
| `event_msg/token_count` | `codex/token-count` | off by default |
| `event_msg/context_compacted`, `compacted` | `codex/compaction` | |
| anything unrecognized | `codex/unknown` | so a new Codex release shows up as a gap, not as data loss |

### Dropped

| Codex | Reason |
|---|---|
| `event_msg/user_message` | duplicate of the response channel |
| `event_msg/agent_message` | duplicate of the response channel |

`response_item/ghost_snapshot` was listed here. It does not belong: it is an
unrecognized type, so it takes the `codex/unknown` path and is carried with
`ignorable: true`. Asserted by the fixture in
`packages/dsh-session-artifact/test/artifact.test.mjs`, which requires exactly one
such row and its type name in `preserved`. Dropping it would have been silent
data loss, which is what the unknown path exists to prevent.

## 5. Three traps in real data

### 5.1 The conversation is written twice

Codex writes each user and agent message on both channels. Measured on a
uniform random sample of 200 rollouts, messages occupy 5.6% of bytes on the
response channel and a comparable share on the event channel.

Keeping both duplicates every message in any downstream view. `dedupeEventChannel`
matches by role and exact text within a bounded window, because the channels
interleave rather than align. On the synthetic fixture this removes 2 of 7
messages.

### 5.2 Tool calls and results can be unpaired

DSH pairs `tool/call` with `tool/result` through `source.callId`. A rollout can
carry a result whose call scrolled out of the retained prefix, or a call that
never completed.

The synthesizer announces a `tool/call` before any result that lacks one, and
records the substitution in `orphanResults`. The fixture contains exactly one
such case, and a test asserts it.

Turn boundaries get the same treatment: a `task_complete` with no matching
`task_started` opens a turn lazily, so every `turn/end` has an opener. Before
this guard the fixture produced one `turn/start` against three `turn/end`.

### 5.3 Web search uses two different identifiers

`web_search_call` names itself with `id`; its paired `web_search_end` uses
`call_id`. Reading the wrong field produces a silently unpaired result. Both
are handled, and a test asserts the pair agrees.

## 6. What a tier costs

Measured on the same uniform random sample, as a share of corpus bytes:

| Tier | Contents | Share | 38 GB becomes | On disk (4.3x) |
|---|---|---|---|---|
| Narrative | messages, tool calls and outputs, turn and step boundaries, context, `session_meta` | 59.9% | 22.8 GB | **5.3 GB** |
| Narrative + readable reasoning | the above plus `content` and `summary` | 60.1% | 22.8 GB | **5.3 GB** |
| Everything except telemetry | the above plus `compacted` records and unmodelled records | 79.9% | 30.4 GB | 7.1 GB |

Two figures drive the choice, and neither is the one an early measurement of
this corpus suggested:

- **Reasoning is 7.0% of bytes, not the majority.** Keeping its readable part
  is free to two significant figures. The argument for preserving it does not
  need a size argument at all.
- **Telemetry is the expensive thing to keep.** `event_msg/item_completed` is
  11.9% of bytes and `event_msg/token_count` 2.8%. Between them they cost about
  1.3 GB on disk and carry no conversational content.

**Correction.** An earlier revision of this document stated that reasoning was
46.7% of corpus bytes. That figure came from sampling the first sixty files in
directory order, which are the oldest and smallest sessions. The uniform sample
puts it at 7.0%. The conclusion — preserve readable reasoning, drop telemetry —
survives, but it rests on the corrected numbers.

## 7. What is lost

Stated plainly, because a mapping document that only lists successes is
misleading.

- **Encrypted reasoning.** Measured on a uniform random sample of 200
  rollouts: reasoning is **7.59%** of corpus bytes, `encrypted_content` is
  **85.2%** of a reasoning record and **6.46%** of the corpus, and the readable
  `content` and `summary` are **0.15%** of the corpus.

  | | Share of corpus | On 38 GB | In an archive (4.3x) |
  |---|---|---|---|
  | `encrypted_content` | 6.46% | 2.46 GB | 0.57 GB |
  | readable reasoning | 0.15% | 0.06 GB | **0.01 GB** |

  **The decision is made per layer, not once.** The archive keeps the
  ciphertext; the DSH import drops it.

  Dropping it from the *import* is right: it is unreadable by any party outside
  OpenAI's systems, and carrying it would add 0.57 GB of noise to a store the
  harness has to scan. It is not that DSH *cannot* carry it — an `ignorable`
  event places no constraint on its payload — but that carrying it buys nothing.

  Keeping it in the *archive* is also right, and costs no design work: the
  archive stores the rollout byte-for-byte, so the ciphertext is retained by
  default and dropping it would require deliberate filtering. The archive is the
  only copy once the source is gone, and a byte-exact copy that quietly omitted
  part of a record would break the property that makes it worth keeping.

  Readable reasoning costs **0.01 GB** and is carried.
- **Token accounting** unless explicitly requested.
- **`base_instructions`**, the full Codex system prompt, several kilobytes per
  session.
- **Ghost snapshots** and other editor state.
- **Subagent nesting.** `sub_agent_activity` records are preserved as unknown
  events; DSH's `parentSession` is not reconstructed from them.
- **Turn identity.** Codex `turn_id` values are not carried; DSH turns are
  positional.

## 8. Reproduction

```bash
npm install
npm run test:packages
```

`test:packages` compiles `dsh-session-artifact` with `tsc` and then runs both
package suites, including `packages/dsh-session-artifact/test/artifact.test.mjs`.

Two commands stood here before — `pnpm run build`, `codex-to-dsh convert
fixtures/rollout-sample.jsonl` and `codex-to-dsh mapping`. The first never
existed (the repository has no pnpm workspace); the other two described a CLI
that was never written. There is no `codex-to-dsh` executable here. The converter
is a library function, and the accounting the `convert` command was said to print
is asserted by the tests instead.
